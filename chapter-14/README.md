# فصل ۱۴ — طراحی داشبوردهای عملیاتی، تاکتیکی و استراتژیک QC در Power BI

**زیرعنوان:** پایش لحظه‌ای، تطابق شیفت‌ها و پایش تجمعی ماهانه

## هدف فصل
کنترل کیفیت در زنجیره کنسانتره و گندله‌سازی چندزمانی است: تصمیم فوری در چند دقیقه، ارزیابی عملکرد شیفت در پایان نوبت، و تصمیم مدیریتی در بازه ماهانه یا فصلی. بنابراین یک نمودار واحد برای همه مخاطبان کافی نیست.

| لایه | افق | مخاطب | پرسش کلیدی |
|---|---|---|---|
| Operational | دقیقه تا ساعت | سرپرست QC/تولید | چه چیزی اکنون نیازمند بررسی است؟ |
| Tactical | شیفت تا چند هفته | QC و سرپرستان | آیا تفاوت شیفت‌ها واقعی و پایدار است؟ |
| Strategic | ماه تا فصل | مدیران | آیا عملکرد بلندمدت بهتر شده و اولویت بهبود چیست؟ |

## ۱۴-۱. تعریف KPI و حدود
KPIهای محصول شامل Fe، SiO₂، Al₂O₃، P، S، رطوبت، CCS و شاخص‌های فیزیکی‌اند؛ KPIهای سنجش شامل نرخ انطباق، OOS، بازآزمایی، TAT و داده ناقص/دیررس‌اند؛ KPIهای پایداری شامل میانگین، پراکندگی، روند و حدود کنترل‌اند.

**حد مشخصات (Spec Limit)** معیار پذیرش محصول است؛ **حد کنترل (Control Limit)** از رفتار آماری فرایند برآورد می‌شود. این‌ها جایگزین یکدیگر نیستند: فرایند ممکن است پایدار ولی خارج از Spec باشد یا در Spec بماند ولی نشانه تغییر آماری داشته باشد. قبل از گزارش، واحد، روش آزمون، ماده، بازه زمانی و نسخه Spec را استاندارد کنید.

## ۱۴-۲. معماری داده
منابع متداول شامل LIMS/Excel آزمایشگاه، PLC/SCADA/Historian، سیستم تولید و جدول Spec هستند. مدل ستاره‌ای توصیه می‌شود:

- `Fact_QC_Result`: هر ردیف نمونه-پارامتر با `SampleID`, زمان‌ها, `Shift`, `Material`, `Parameter`, `Value`, `Unit`, روش, Batch و پرچم کیفیت.
- ابعاد تاریخ/شیفت، واحد/خط، ماده، آزمون، پارامتر و Spec نسخه‌دار.
- Factهای جداگانه برای تگ‌های فرایندی و KPI تجمیعی؛ Factها را بی‌واسطه به هم وصل نکنید.
- فرمت Long (ستون‌های Parameter و Value) برای فیلتر و توسعه مناسب‌تر است.

فایل نمونه شیت‌های `Fact_QC_Result`, `Fact_Process_Tag`, `Fact_Monthly_KPI` و ابعاد متناظر دارد. جزئیات رابطه‌ها در [آموزش Power BI](POWER_BI_TUTORIAL.md) آمده است.

## ۱۴-۳. آماده‌سازی و زمان
در Power Query نوع داده و واحدها را یکسان کنید، نام‌ها و شناسه‌ها را پاک‌سازی کنید، رکورد مشکوک را علامت بزنید و نسخه/تاریخ اثر Spec را حفظ کنید. سه timestamp متفاوت‌اند: `SampleDateTime` (نمونه‌برداری)، `ResultDateTime` (تولید/تأیید نتیجه) و `IngestionDateTime` (ورود به سامانه تحلیلی). مبنای زمانی KPI را در خود گزارش مشخص کنید.

نمونه شیفت: A از 07:00 تا 15:00، B از 15:00 تا 23:00 و C از 23:00 تا 07:00 روز بعد. تعریف `ShiftDate` برای شیفت C باید بر اساس عرف رسمی کارخانه باشد؛ از حدس در مرز نیمه‌شب اجتناب کنید.

## ۱۴-۴. KPIهای DAX
نمونه‌های پایه با نام جدول فایل آموزشی:

```DAX
Results = COUNTROWS ( Fact_QC_Result )
Average Value = AVERAGE ( Fact_QC_Result[Value] )
StdDev Value = STDEV.S ( Fact_QC_Result[Value] )

OOS Results =
CALCULATE ( COUNTROWS ( Fact_QC_Result ), Fact_QC_Result[IsConform] = 0 )

Conformance % = DIVIDE ( [Results] - [OOS Results], [Results] )
```

حدود باید برای ماده/پارامتر/نسخه صحیح خوانده شوند؛ پرچم `IsConform` در دیتاست آموزشی موجود است، اما در سامانه واقعی باید طبق Spec زمان‌مند و معتبر محاسبه شود. در حد دوطرفه، انطباق یعنی `Value >= LSL` و `Value <= USL`; حد ناموجود را به‌عنوان شرط غایب تفسیر کنید، نه صفر.

## ۱۴-۵. داشبورد عملیاتی و تازگی
صفحه عملیاتی باید آخرین داده، وضعیت انطباق، مقدار اخیر، فاصله تا حد، روند کوتاه‌مدت و هشدارهای قابل اقدام را در یک نگاه نشان دهد. Freshness باید از آخرین `IngestionDateTime` معتبر سنجیده شود، نه صرفاً زمان نمونه‌برداری یا نتیجه. آستانه تازگی را با تناوب واقعی نمونه‌گیری و TAT تعیین کنید.

هشدار مفید شامل پارامتر، مقدار، حد، شدت، زمان، مسئول پاسخ و اقدام پیشنهادی است؛ جدول `Dim_ActionRule` در نمونه قابل استفاده است. هشدار، توصیه برای بررسی است و به‌تنهایی مجوز کنترل خودکار نیست. تعداد slicerها را محدود کنید، رنگ معنایی ثابت داشته باشید و Drill-through تا جزئیات SampleID فراهم کنید.

## ۱۴-۶. داشبورد تاکتیکی شیفت
مقایسه شیفت باید همراه با حجم نمونه، نرخ داده ناقص/دیررس، توزیع و percentiles، بازه زمانی، نوع محصول/خوراک و در صورت امکان شرایط فرایند ارائه شود. Boxplot و Violin برای دیدن توزیع مناسب‌اند؛ در Power BI از visual معتبر یا نمودارهای جایگزین استفاده کنید.

اختلاف میانگین یا نرخ OOS به‌تنهایی تفاوت معنادار را اثبات نمی‌کند. استقلال، توزیع، طرح نمونه‌گیری، حجم نمونه و عوامل مخدوش‌کننده را ارزیابی کنید. آزمون‌های ANOVA یا ناپارامتری را بر اساس فرض‌ها انتخاب کنید؛ دستورالعمل‌های اجرایی در [Python](PYTHON_TUTORIAL.md) و [Minitab](MINITAB_TUTORIAL.md) هستند.

## ۱۴-۷. داشبورد استراتژیک و قابلیت
نمای مدیریتی شامل KPI ماه جاری در برابر هدف، روند ۱۲ ماهه، Pareto علل OOS، پایداری و در صورت مجاز بودن قابلیت فرایند است. `Fact_Monthly_KPI` داده تجمیعی آموزشی دارد؛ اعداد آن را با واقعیت رکوردی کنترل کنید.

```text
Cp  = (USL - LSL) / (6 × s_within)
Cpk = min((USL - mean)/(3 × s_within), (mean - LSL)/(3 × s_within))
```

این فرمول‌ها برای حالت نرمال و دوطرفه‌اند. پیش از تفسیر، پایداری، نمایندگی داده، کفایت نمونه، اعتبار Spec و توزیع را بررسی کنید. برای توزیع غیرنرمال، روش مناسب همان توزیع/تبدیل را انتخاب کنید. حدود کنترل را به‌جای Spec وارد فرمول نکنید.

## ۱۴-۸. UX، حاکمیت و تحویل
- یک معنای ثابت برای رنگ‌ها: سبز قابل قبول، زرد نیازمند توجه، قرمز عدم انطباق/ریسک؛ دسترس‌پذیری را رعایت کنید.
- دقت اعشار را با روش آزمایش هماهنگ کنید؛ واحد، منبع Spec و مبنای زمان را نشان دهید.
- Drill-through تا SampleID، زمان، روش، Batch و نتیجه فراهم کنید.
- برای سایت/واحد، RLS را با کاربران آزمایشی در Power BI Service آزمون کنید؛ نمایش نام فرد فقط با مجوز.
- مدل ستاره‌ای، روابط یک‌به‌چند و تجمیع ماهانه به کارایی کمک می‌کنند؛ در صورت پشتیبانی از Incremental Refresh بهره ببرید.

**چک‌لیست:** تعریف KPI و زمان روشن است؟ نسخه Spec قابل ردیابی است؟ Freshness بر اساس ingestion معتبر است؟ مقایسه شیفت با تعداد نمونه همراه است؟ پایداری و توزیع پیش از قابلیت بررسی شده‌اند؟ RLS و تجمیع با منبع کنترل شده‌اند؟
